# 飞书项目中心本地脚本说明

这个仓库保留项目总览、开票计划、开票明细统一、供应商成本、开票核对和本地网页控制台。

协作者、角色成员、精细化权限、日常视图、老板驾驶舱、同步日志、权限自动化都不再由本地脚本维护，统一在飞书里手动配置或用飞书自身能力处理。

日常同步方向改为：飞书自带同步只负责更新 9 张 `源_` 表；项目总览、项目开票计划、开票明细统一、项目供应商成本和项目阶段由本地网页按钮统一刷新。

## 新电脑使用

新电脑先安装 Node.js 20 以上版本，登录 Codex，并授权飞书 MCP。

```bash
git clone https://github.com/wuinin2025-boop/ze-feishu-project.git
cd ze-feishu-project
npm install
npm test
npm run setup:invoice-model
npm run verify:invoice
npm run control
```

保持终端窗口打开，然后访问：

```text
http://localhost:3000
```

已经拉过代码的电脑：

```bash
cd /path/to/ze-feishu-project
git pull origin main
npm install
npm test
npm run control
```

## 当前保留的核心表

- `项目总览表`：项目主表。`项目分类管理` 只在这里人工维护，取值为 `经营项目`、`行政/内部项目`、`走账项目`；`项目阶段` 由本地脚本根据项目情况自动写入。
- `项目线索表`：线索项目主表。
- `项目进度表`：日常任务和项目日报。经营项目在 `项目总览表` 已经维护为 `经营项目` 后，本地同步会检查是否已有进度记录；没有时自动新增一条默认任务，方便人员继续拆任务。
- `项目开票计划表`：旧项目和新项目的统一开票计划执行表。旧项目来自 `（旧项目）开票计划补录表`，新项目来自审批通过的 `源_立项申请` 开票计划。唯一键为 `项目编号-计划期次`。
- `开票明细统一表`：三张 `源_开票明细` 的统一结果表，用来承载实际开票、收款、欠款、红冲、项目匹配、计划匹配。
- `项目供应商成本表`：每条 PO 一行，按项目展示供应商、PO 成本、付款申请、实际付款、是否收票和异常情况。付款申请找不到 PO 时会生成异常行，方便人工处理。
- `（旧项目）开票计划补录表`：旧项目人工补录表，当前仍在人工维护，本地脚本不能写入、清理或重建这张表。

## 可以删除或已经删除的旧表

这些表不再由本地脚本依赖：

- `老板驾驶舱关键数据表`
- `项目开票进度表`
- `开票明细归集表`
- `同步日志`
- `系统_人员权限表`
- `系统_负责人变更记录表`
- `系统_立项公司配置表`

`系统_历史开票收款明细` 目前本地脚本也没有引用。它更像旧历史财务表，建议确认旧项目补录已完成、没有人工查询需求后再删除。

## 源表使用情况

飞书自带同步应保持 9 张源表自动更新：

- `源_集熠项目台账`
- `源_冶堂项目台账`
- `源_亦所项目台账`
- `源_立项申请`：读取审批通过的新项目开票计划。
- `源_PO申请`
- `源_付款申请`
- `源_集熠开票明细`
- `源_冶堂开票明细`
- `源_亦所开票明细`

本地网页按钮负责更新目标表：

- 三张项目台账和 `源_立项申请` 更新 `项目总览表`。
- `项目总览表` 中分类为 `经营项目` 且尚无进度记录的项目，会新增到 `项目进度表`。
- `源_立项申请` 和 `（旧项目）开票计划补录表` 更新 `项目开票计划表`。
- 三张开票明细更新 `开票明细统一表`。
- `源_PO申请`、`源_付款申请` 和 `供应商付款` 更新 `项目供应商成本表`。其中 `源_PO申请` 的 `金额1` 是供应商成本，`源_付款申请` 是付款申请记录，`供应商付款` 的实际付款金额由财务人工维护，本地脚本只读取它判断是否真实付款。

具体配置见：

- `docs/feishu-automation-setup.md`

## 开票明细是否自动更新

`开票明细统一表` 不再依赖飞书自动化监听三张 `源_开票明细`。

三张源明细表、`源_PO申请`、`源_付款申请` 新增或更新后，打开本地控制台点击“同步项目、开票和供应商数据”，即可刷新 `开票明细统一表`、`项目开票计划表`、`项目供应商成本表` 和 `项目总览表` 汇总字段。

本地网页入口：

```bash
npm run control
```

打开：

```text
http://localhost:3000
```

如果端口被占用：

```bash
PORT=3001 npm run control
```

打开：

```text
http://localhost:3001
```

## 脚本命令

创建或修复开票模型结构：

```bash
npm run setup:invoice-model
```

应急同步开票计划和开票明细：

```bash
npm run sync:invoice
```

这个命令现在会同步：

- `项目总览表`
- `项目开票计划表`
- `开票明细统一表`
- `项目供应商成本表`

核对开票计划和开票明细：

```bash
npm run verify:invoice
```

运行自动测试：

```bash
npm test
```

## 安全规则

- 不能写入任何 `源_` 表。
- 不能写入 `（旧项目）开票计划补录表`。
- 不能让本地脚本维护协作者、角色成员或高级权限。
- 不能再创建 `老板驾驶舱关键数据表`。
- 不能再写入 `项目开票进度表`、`开票明细归集表`、`同步日志`。
- `项目分类管理` 只在 `项目总览表` 人工维护，下游表通过 `关联项目` 和公式字段引用。
- `项目阶段` 不人工维护，由本地脚本根据立项、结算、PO、开票、付款情况自动写入。
- `项目状态` 由本地脚本按开票、收款、结算自动写入，但如果人工标记为 `暂停`，同步时会保留暂停。
- `项目进度表` 只自动补经营项目的第一条默认任务，不会覆盖人员后续手工填写的任务内容。

## 当前匹配规则

- 源发票按项目匹配到最早未完成的计划期次。
- 金额不一致时标记为 `金额异常待确认`，不自动滚动到下一期。
- 正负金额相同的发票对视为红冲抵消，不纳入统计。
- `行政/内部项目` 不进入老板驾驶舱统计。
- `经营项目` 和 `走账项目` 必须分开展示、分开统计、分开看风险。
