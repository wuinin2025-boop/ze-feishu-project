# 飞书自动化配置清单

## 当前执行口径

这份文档保留为历史配置参考。当前正式口径已经调整：

- 飞书自带同步只负责让 9 张 `源_` 表保持更新。
- `项目总览表`、`项目开票计划表`、`开票明细统一表` 不再用复杂飞书自动化公式维护。
- 以上三张业务表统一通过本地网页控制台刷新。
- `（旧项目）开票计划补录表` 仍然只允许人工补录，本地脚本只读取，不写入、不清理、不迁移。
- `项目分类管理` 仍然只在 `项目总览表` 人工维护。
- `项目阶段` 由本地脚本根据项目情况自动写入，例如已开票金额达到计划口径时写入 `全部开票`。

本地控制台启动方式：

```bash
npm run control
```

打开：

```text
http://localhost:3000
```

下面内容仅作为飞书自动化方案的历史参考，不建议继续按下面步骤配置项目总览、开票计划、开票明细同步。

---

这份文档用于把 9 张 `源_` 表的数据自动更新到现有业务表里，尽量减少本地脚本依赖。

核心原则：

- `源_` 表只作为审批或外部系统同步源，不手动编辑。
- 日常业务表尽量通过飞书自动化、关联字段、查找引用和公式更新。
- `项目总览表` 是项目主表，`源_立项申请` 审批通过后应自动新增或更新项目记录。
- 其他业务表优先关联 `项目总览表`，再从项目主表引用项目编号、项目名称、立项公司、项目分类、负责人等字段。
- 本地脚本只保留为应急核对工具，不作为日常交接流程。

## 9 张源表

| 源表 | 目标表 | 用途 |
| --- | --- | --- |
| `源_集熠项目台账` | `项目总览表` | 同步集熠项目基础信息、金额、阶段、负责人 |
| `源_冶堂项目台账` | `项目总览表` | 同步冶堂项目基础信息、金额、阶段、负责人 |
| `源_亦所项目台账` | `项目总览表` | 同步亦所项目基础信息、金额、阶段、负责人 |
| `源_立项申请` | `项目总览表`、`项目开票计划表` | 审批通过后新增项目，并生成新项目开票计划 |
| `源_PO申请` | `供应商付款` | 同步 PO、供应商、项目、报价或成本信息 |
| `源_付款申请` | `供应商付款` | 同步实际付款申请、付款日期、付款金额、付款状态 |
| `源_集熠开票明细` | `开票明细统一表` | 同步集熠实际开票、收款、欠款 |
| `源_冶堂开票明细` | `开票明细统一表` | 同步冶堂实际开票、收款、欠款 |
| `源_亦所开票明细` | `开票明细统一表` | 同步亦所实际开票、收款、欠款 |

## 自动化总规则

每张源表建议建立一套自动化流程：

1. 触发条件：当源表新增记录或记录更新。
2. 触发过滤：`SourceID` 不为空；如果源表没有稳定唯一字段，再使用记录 ID。
3. 先查找目标表中是否已有对应记录。
4. 找到则更新目标记录。
5. 找不到则新增目标记录。
6. 目标表不要反向写入 `源_` 表。

如果飞书自动化不支持“新增或更新”合并动作，就拆成两个分支：

- 分支一：查找到目标记录 -> 更新记录。
- 分支二：未查找到目标记录 -> 新增记录。

## 唯一键建议

### `项目总览表`

优先用 `项目编号` 作为项目唯一识别。

配置建议：

- 查找条件一：`项目编号 = 源表.项目编号`
- 辅助字段：`源记录ID = 源表.SourceID`
- 辅助字段：`数据来源 = 源表名称`

如果源记录没有项目编号，先不要自动新增正式项目，建议进入异常视图人工确认。

### `项目开票计划表`

唯一键：

```text
计划唯一键 = 项目编号 + "-" + 计划期次
```

这里的计划期次来自：

```text
开票计划（根据合同约定开票频次新增对应明细）_开票期次(次)
```

### `开票明细统一表`

唯一键：

```text
明细唯一键 = 源表名称 + "|" + SourceID
```

不要用发票编号做唯一键。原因是存在红冲、海外客户空发票号、历史数据补录等特殊情况。

### `供应商付款`

建议拆成两个来源字段：

- `源PO申请记录ID`
- `源付款申请记录ID`

如果当前 `供应商付款` 还没有 `源PO申请记录ID` 字段，建议新增。现有字段里已经有 `源付款申请记录ID`。

## 自动化三：`源_立项申请` 进入 `项目开票计划表`

## 目标表之间的引用关系

### `项目开票计划表`

必须关联：

- `关联项目` -> `项目总览表`

建议用查找引用或公式带出：

- `项目编号`
- `项目名称`
- `立项公司`
- `当前项目负责人`
- `项目分类管理`
- `老板驾驶舱分组`

### `开票明细统一表`

必须关联：

- `关联项目` -> `项目总览表`

后续可以关联：

- `关联计划` -> `项目开票计划表`

建议用查找引用或公式带出：

- `项目分类管理`
- `老板驾驶舱分组`
- `立项公司`
- `当前项目负责人`

### `供应商付款`

必须关联：

- `关联项目` -> `项目总览表`

后续可以关联：

- `关联PO`
- `关联付款申请`

从 `关联项目` 引用：

- 项目编号
- 项目名称
- 立项公司
- 当前项目负责人
- 项目分类管理

## 推荐配置顺序

1. 先配置 `源_立项申请 -> 项目总览表`。
2. 再配置三张项目台账 -> `项目总览表`。
3. 再配置 `源_立项申请 -> 项目开票计划表`。
4. 再配置三张开票明细 -> `开票明细统一表`。
5. 最后配置 `源_PO申请`、`源_付款申请` -> `供应商付款`。
6. 配完后检查每张目标表是否存在重复记录。
7. 确认无误后，本地 `sync:invoice` 只作为应急核对工具，不再作为日常操作。

## 验收标准

- `源_立项申请` 审批通过后，`项目总览表` 自动新增或更新项目。
- `源_立项申请` 的每一期开票计划自动进入 `项目开票计划表`。
- 三张项目台账新增或更新后，`项目总览表` 对应项目自动更新。
- 三张开票明细新增或更新后，`开票明细统一表` 自动新增或更新。
- `源_PO申请`、`源_付款申请` 审批通过后，`供应商付款` 自动新增或更新。
- `项目分类管理` 仍然只在 `项目总览表` 人工维护。
