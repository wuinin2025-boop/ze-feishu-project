# 本地同步总控说明

这份说明对应本地命令 `npm run sync:all` 和本地网页控制台 `npm run control`。

## 打开本地网页控制台

```bash
npm run control
```

启动后打开：

```text
http://localhost:3000
```

页面里可以点击演练、正式同步、只同步开票回款、只同步人员权限、只整理日常视图，并能看到实时日志。

运行控制台的终端窗口需要一直保持打开。如果 `3000` 端口已被占用，可以改用：

```bash
PORT=3001 npm run control
```

然后打开 `http://localhost:3001`。

## 一键同步全部

```bash
npm run sync:all
```

这个命令会按顺序做这些事：

1. 基础检查：先确认本地脚本没有明显错误。
2. 同步开票回款：把源立项、源开票明细、旧项目补录整理到 `项目开票进度表` 和 `开票明细归集表`。
3. 检查开票数据：确认开票进度、发票归集、旧项目补录数量和金额能对上。
4. 刷新项目状态：把 `项目总览表` 的项目状态按规则更新。
5. 同步人员权限：按人员身份、项目负责人、项目成员、负责人交接记录刷新飞书权限。
6. 检查人员权限：确认关键权限设置符合当前脚本。
7. 整理日常视图：隐藏同步字段和权限辅助字段，并整理 `项目开票进度表` 的 `开票逾期`、`回款逾期` 视图。

## 常用单独按钮

只同步开票回款：

```bash
npm run sync:all -- --only=invoice,verify-invoice
```

只刷新项目状态：

```bash
npm run sync:all -- --only=project-status
```

只同步人员权限：

```bash
npm run sync:all -- --only=permissions,verify-permissions
```

只整理日常视图：

```bash
npm run sync:all -- --only=views
```

先演练、不写飞书：

```bash
npm run sync:all -- --dry-run
```

查看所有可用步骤：

```bash
npm run sync:all -- --list
```

独立逾期回款项目明细表默认不再同步。如果确实还要临时刷新，可以手动运行：

```bash
npm run sync:all -- --only=boss-dashboard
```

## 当前数据闭环

`源_` 表是原始数据，只读，不由脚本写入。

`sync:invoice` 当前会读取：

- `源_立项申请`
- 三张 `源_开票明细`
- `项目总览表`

它会写入：

- `开票明细归集表`
- `（旧项目）开票计划补录表` 中脚本自动生成的旧项目行
- `项目开票进度表`
- `同步日志`

新项目后续从 `源_立项申请` 进入 `项目开票进度表`。旧项目补录表用于把历史项目计划补完整，补完后再通过开票同步进入开票进度。

## 人员权限规则

- 管理员可以管理全部业务数据。
- 项目负责人只能查看和编辑自己负责、参与、执行或创建的项目数据。
- 普通员工只能查看和编辑自己参与、执行或创建的项目进度数据，不能查看财务表。
- 项目负责人和普通员工都可以新增任务，也可以删除自己有权管理的任务。
- 同一个人既是某些项目的负责人、又是其他项目的成员时，权限按每条项目记录关联的人来判断，不会展开全部公司项目。

## 协作者添加失败排查

“项目成员”字段中已经出现某个人，不代表这个账号一定仍是当前多维表格的有效协作者。历史账号、外部账号或已离开当前组织的账号，可能保留在旧记录中，但无法加入高级权限角色。

如果同步输出出现 `1063002 Permission denied`、`1254002 Fail` 或“权限角色状态=同步失败”：

1. 打开飞书多维表格的“高级权限”。
2. 打开“普通员工”角色的成员列表，点击添加成员。
3. 在组织成员选择器中搜索该员工。
4. 如果搜索不到，先恢复该员工的当前组织账号，或邀请当前账号进入本组织。
5. 回到 `系统_人员权限表`，重新选择“飞书用户”字段中的当前账号；项目成员中若引用的是旧账号，也要重新选择。
6. 再运行 `npm run sync:all -- --only=permissions,verify-permissions`。

当前周子烨的账号属于这种情况：她是项目成员，但在本组织的协作者选择器中搜索不到，因此飞书接口拒绝添加。账号恢复或重新邀请后，脚本即可继续同步。

## 当前注意事项

- 独立的 `逾期回款项目明细表` 默认不再维护，日常从 `项目开票进度表` 的 `开票逾期` 和 `回款逾期` 视图查看。
- 旧项目手动补录后同步到 `项目开票进度表` 的逻辑，后续可从现有开票同步中拆成更清楚的单独按钮。
