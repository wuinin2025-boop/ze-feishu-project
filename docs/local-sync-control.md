# 本地同步总控说明

这份说明对应本地命令 `npm run sync:all`，以后线上网页控制台也可以按同样的按钮逻辑来做。

## 一键同步全部

```bash
npm run sync:all
```

这个命令会按顺序做这些事：

1. 基础检查：先确认本地脚本没有明显错误。
2. 同步开票回款：把源立项、源开票明细、旧项目补录整理到 `项目开票进度表` 和 `开票明细归集表`。
3. 检查开票数据：确认开票进度、发票归集、旧项目补录数量和金额能对上。
4. 刷新项目状态：把 `项目总览表` 的项目状态按规则更新。
5. 刷新老板看板：生成老板能直接看的逾期回款项目明细。
6. 同步人员权限：按人员身份、项目负责人、项目成员、负责人交接记录刷新飞书权限。
7. 检查人员权限：确认关键权限设置符合当前脚本。
8. 整理日常视图：隐藏同步字段和权限辅助字段，让日常填写界面简单一点。

## 常用单独按钮

只同步开票回款：

```bash
npm run sync:all -- --only=invoice,verify-invoice
```

只刷新项目状态和老板看板：

```bash
npm run sync:all -- --only=project-status,boss-dashboard
```

只同步人员权限：

```bash
npm run sync:all -- --only=permissions,verify-permissions
```

只整理日常视图：

```bash
npm run sync:all -- --only=views
```

先演练、不写飞书：

```bash
npm run sync:all -- --dry-run
```

查看所有可用步骤：

```bash
npm run sync:all -- --list
```

## 当前数据闭环

`源_` 表是原始数据，只读，不由脚本写入。

`sync:invoice` 当前会读取：

- `源_立项申请`
- 三张 `源_开票明细`
- `项目总览表`

它会写入：

- `开票明细归集表`
- `（旧项目）开票计划补录表` 中脚本自动生成的旧项目行
- `项目开票进度表`
- `同步日志`

新项目后续从 `源_立项申请` 进入 `项目开票进度表`。旧项目补录表用于把历史项目计划补完整，补完后再通过开票同步进入开票进度。

## 目前仍需要重构的地方

- 权限脚本还需要按新的干净模型重写：管理员、项目负责人、项目成员、离职人员。
- 管理员对 `源_` 表应只读，这一点需要在新版权限脚本中统一处理。
- 老板看板后续还要继续压缩成更像老板看的项目级结果。
- 旧项目手动补录后同步到 `项目开票进度表` 的逻辑，需要从现有开票同步里拆成更清楚的单独按钮。
