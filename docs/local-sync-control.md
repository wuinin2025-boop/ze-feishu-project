# 本地同步总控说明

这份说明对应本地命令 `npm run sync:all` 和本地网页控制台 `npm run control`。

## 打开本地网页控制台

```bash
npm run control
```

启动后打开：

```text
http://localhost:3000
```

页面里可以点击演练、正式同步、只同步开票回款、只整理日常视图，并能看到实时日志。

运行控制台的终端窗口需要一直保持打开。如果 `3000` 端口已被占用，可以改用：

```bash
PORT=3001 npm run control
```

然后打开 `http://localhost:3001`。

## 一键同步全部

```bash
npm run sync:all
```

这个命令会按顺序做这些事：

1. 基础检查：先确认本地脚本没有明显错误。
2. 同步开票回款：把源立项、源开票明细、旧项目补录整理到 `项目开票进度表` 和 `开票明细归集表`。
3. 检查开票数据：确认开票进度、发票归集、旧项目补录数量和金额能对上。
4. 刷新项目状态：把 `项目总览表` 的项目状态按规则更新。
5. 整理日常视图：隐藏同步字段和辅助字段，并整理 `项目开票进度表` 的 `开票逾期`、`回款逾期` 视图。

## 常用单独按钮

只同步开票回款：

```bash
npm run sync:all -- --only=invoice,verify-invoice
```

只刷新项目状态：

```bash
npm run sync:all -- --only=project-status
```

只整理日常视图：

```bash
npm run sync:all -- --only=views
```

先演练、不写飞书：

```bash
npm run sync:all -- --dry-run
```

查看所有可用步骤：

```bash
npm run sync:all -- --list
```

独立逾期回款项目明细表默认不再同步。如果确实还要临时刷新，可以手动运行：

```bash
npm run sync:all -- --only=boss-dashboard
```

## 当前数据闭环

`源_` 表是原始数据，只读，不由脚本写入。

`sync:invoice` 当前会读取：

- `源_立项申请`
- 三张 `源_开票明细`
- `项目总览表`

它会写入：

- `开票明细归集表`
- `（旧项目）开票计划补录表` 中脚本自动生成的旧项目行
- `项目开票进度表`
- `同步日志`

新项目后续从 `源_立项申请` 进入 `项目开票进度表`。旧项目补录表用于把历史项目计划补完整，补完后再通过开票同步进入开票进度。

## 人员权限维护

人员协作者、角色成员和精细化权限现在以飞书高级权限后台为准，后续调整也直接在飞书高级权限中维护。本仓库不再从 `系统_人员权限表` 同步角色成员，也不再检查人员角色同步状态。

仍需保留的权限原则：

- 管理员可以管理全部业务数据。
- 项目负责人只应查看和编辑自己负责、参与、执行或创建的项目数据。
- 普通员工只应查看和编辑自己参与、执行或创建的项目进度数据，不能查看财务表。
- 项目负责人和普通员工可以新增任务，也可以删除自己有权管理的任务。
- 同一个人既是某些项目的负责人、又是其他项目的成员时，权限按每条项目记录关联的人来判断，不应展开全部公司项目。

## 停用的系统表

以下系统表不再作为权限源，建议在飞书中隐藏或归档，避免交接误解：

- `系统_人员权限表`
- `系统_负责人变更记录表`

如果确认不再需要保留历史记录，可以在飞书中导出备份后删除。删除前要确认没有公式、关联、视图或人工流程继续引用这些表。

## 当前注意事项

- 独立的 `逾期回款项目明细表` 默认不再维护，日常从 `项目开票进度表` 的 `开票逾期` 和 `回款逾期` 视图查看。
- 旧项目手动补录后同步到 `项目开票进度表` 的逻辑，后续可从现有开票同步中拆成更清楚的单独按钮。
