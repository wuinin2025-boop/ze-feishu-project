# 项目人员补空与同步稳定性修复实施计划

> **供自动执行工具使用：** 必须逐项执行并在每项完成后复核。优先使用子任务驱动开发；若当前客户端没有对应能力，则在本任务中按检查点顺序执行。

**目标：** 恢复缺失的项目负责人和参与人员，保护人工维护值，并修复源记录技术编号误更新、供应商成本全量重建和定时失败不重试的问题。

**实现方式：** `源_立项申请`与三家公司项目台账继续只读。同步脚本读取完整人员字段，对目标表执行“仅空白可补”的差异更新；项目和供应商成本改用稳定业务编号识别，源记录技术编号只用于追踪；定时服务在临时失败后自动重试。

**技术环境：** Node.js、飞书多维表格接口、Node.js 内置测试框架、服务器定时服务。

## 全局约束

- 不写任何`源_`表。
- 不写、清理或迁移`（旧项目）开票计划补录表`。
- 不自动填写或覆盖`项目分类管理`。
- `当前项目负责人`和`项目参与人员`只补空，已有任何值都不得覆盖或追加。
- 参与人员只取策划、设计、执行并去重，不重复加入当前项目负责人。
- 供应商成本稳定键迁移必须原地更新，禁止删除全部记录后重建。
- 只有真实业务字段变化才更新`最近同步时间`。
- 正式同步前必须通过试算，并确认不存在供应商成本全量删除或全量创建。
