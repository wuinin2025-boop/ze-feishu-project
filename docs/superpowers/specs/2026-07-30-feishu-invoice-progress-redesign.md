# 飞书项目开票进度表重构设计

## 目标

把当前逻辑错误的 `开票回款总览` 停用为旧逻辑，重新建设 `项目开票进度表`。

这张表给老板、管理员和项目负责人看项目开票与回款进度，回答四个问题：

- 每个项目计划开几次票。
- 每次计划什么时候开、开多少钱。
- 实际有没有开票、有没有回款。
- 哪些开票或回款即将到期、已经逾期、金额异常。

## 核心结论

采用“飞书原生同步和自动化为主，轻量 API 校准和权限同步为辅，网页后台只做管理员手动触发”的方案。

不在旧 `开票回款总览` 逻辑上修补。先新建 `项目开票进度表_试运行`，核对通过后再停用旧表并改正式名称。

## 只读边界

所有 `源_` 表都是只读表，不能修改字段、记录、公式、视图、自动化和权限。

目标业务表可以新增和修改，包括：

- `项目开票进度表_试运行`
- `开票明细归集表`
- `（旧项目）开票计划补录表`
- `同步日志`
- `权限变更日志`

## 表结构分工

| 表名 | 类型 | 用途 |
|---|---|---|
| `源_立项申请` | 只读源表 | 提供立项项目信息、新项目开票计划、立项时项目负责人 |
| 三张 `源_开票明细` | 只读源表 | 提供实际发票、开票日期、回款日期、回款金额、备注 |
| `开票明细归集表` | 目标辅助表 | 将三张开票明细统一为一张发票一行，用于匹配项目开票进度 |
| `（旧项目）开票计划补录表` | 目标人工表 | 补旧项目开票计划，初始化后由管理员修正 |
| `项目开票进度表_试运行` | 目标主表 | 老板和项目负责人查看的开票回款进度表 |
| `同步日志` | 目标日志表 | 记录自动化、API 校准、异常和手动触发结果 |
| `权限变更日志` | 目标日志表 | 记录人员权限新增、移除、失败和原因 |

## 数据粒度

`项目开票进度表` 的一行代表一个项目的一个当前执行开票节点。

当前执行开票节点原则上等于一张应开或已开的发票：

- 计划未执行时，一行代表一张应开的计划发票。
- 已实际开票时，一行代表一张真实发票。
- 如果立项计划是 2 次，实际开了 3 张发票，最终表里是 3 行。
- 原始立项计划仍保留在字段中，用于解释差异。

## 新旧项目来源

申请编号小于 `202607270009` 的项目按旧项目处理。

旧项目没有可靠开票计划，先从三张开票明细按项目编号归集：

- 有实际发票时，按开票日期排序生成期次 `1、2、3...`。
- 已有发票行的计划金额默认等于实际开票金额。
- 已有发票行的计划开票日期默认等于实际开票日期。
- 已有发票行的开票状态为 `已开票`。
- 已有发票行的生成状态为 `根据历史发票自动生成`。
- 如果立项金额大于已开票金额，自动追加最后一期，金额为 `立项金额 - 已开票金额`。
- 如果完全没有发票明细，自动生成 1 行 `待人工补充`。

申请编号大于等于 `202607270009` 的项目按新项目处理。

新项目从 `源_立项申请` 读取展开后的开票计划记录：

- `预计开票总次数`
- `开票期次`
- `预计开票日期`
- `预计开票金额`
- `预计回款日期`
- 立项时项目负责人

`202607270006` 到 `202607270008` 虽然可能有测试开票计划字段，但不进入正式新项目逻辑。

## 主表核心字段

| 字段 | 取数逻辑 |
|---|---|
| `项目编号` | 源立项或开票明细项目编号 |
| `项目名称` | 源立项优先，开票明细作为核对 |
| `客户名称` | 源立项或开票明细 |
| `立项时项目负责人` | 取立项时项目负责人，用于展示和追溯 |
| `当前权限负责人` | 取项目总览当前负责人，用于权限，不覆盖立项负责人 |
| `立项开票总次数` | 新项目取 `预计开票总次数`，旧项目取初始化或补录结果 |
| `当前开票总次数` | 按当前执行节点计算，实际拆票时可大于立项次数 |
| `原计划期次` | 源立项或旧项目补录中的计划期次 |
| `当前执行期次` | 当前进度表实际展示期次 |
| `原计划开票金额` | 源立项或旧项目补录金额 |
| `当前计划开票金额` | 当前执行节点金额 |
| `计划开票日期` | 源立项或旧项目补录日期 |
| `预计回款日期` | 源立项或旧项目补录日期 |
| `实际开票日期` | 取开票明细表 `开票日期` |
| `实际开票金额` | 取开票明细表 `开票额` |
| `回款日期` | 取开票明细表 `收款日期` 或回款日期 |
| `回款金额` | 取开票明细表 `收款额` 或回款金额 |
| `未开票金额` | `当前计划开票金额 - 实际开票金额`，小于 0 时标异常 |
| `未回款金额` | `实际开票金额 - 回款金额`，小于 0 时标异常 |
| `逾期天数` | 按开票或回款到期日计算 |
| `逾期金额` | 开票逾期取未开票金额，回款逾期取未回款金额 |
| `开票状态` | 自动计算 |
| `回款状态` | 自动计算 |
| `综合状态` | 老板主要查看状态 |
| `计划备注` | 引用 `（旧项目）开票计划补录表` 备注，或源计划备注 |
| `发票备注` | 引用开票明细表备注 |
| `差异说明` | 自动说明拆票、金额不一致、待人工确认等 |
| `生成状态` | 自动生成、人工补录、实际拆分开票、待人工确认等 |

## 状态规则

开票状态按当前执行节点计算：

| 条件 | 开票状态 |
|---|---|
| 实际开票金额大于等于当前计划开票金额 | `已开票` |
| 实际开票金额大于 0 且小于当前计划开票金额 | `部分开票` |
| 未开票且计划开票日期未来 7 天以内 | `即将到期开票` |
| 未开票且已超过计划开票日期 | `开票逾期` |
| 未开票且距离计划开票日期超过 7 天 | `未到期` |
| 缺少计划金额或计划日期 | `待人工补充` |

回款状态按实际开票和回款计算：

| 条件 | 回款状态 |
|---|---|
| 未开票 | `待开票` |
| 已开票且回款金额大于等于实际开票金额 | `已回款` |
| 已开票且回款金额大于 0 且小于实际开票金额 | `部分回款` |
| 已开票且超过预计回款日期仍未收齐 | `回款逾期` |
| 已开票且未到预计回款日期 | `待回款` |
| 缺少预计回款日期 | `待补预计回款日期` |

综合状态优先级：

1. `金额异常待核对`
2. `项目负责人待处理`
3. `回款逾期`
4. `开票逾期`
5. `即将到期开票`
6. `部分回款`
7. `待回款`
8. `已回款`
9. `未到期`
10. `待人工补充`

## 实际拆票规则

当实际开票次数和立项计划次数不一致时，不修改源立项计划。

以项目金额 1000 元为例：

| 类型 | 期次 | 金额 |
|---|---:|---:|
| 原计划 | 第 1 期 | 300 |
| 原计划 | 第 2 期 | 700 |
| 实际开票 | 第 1 张 | 200 |
| 实际开票 | 第 2 张 | 300 |
| 实际开票 | 第 3 张 | 500 |

`项目开票进度表` 最终生成 3 行当前执行节点：

| 当前执行期次 | 当前计划开票金额 | 实际开票金额 | 差异说明 |
|---:|---:|---:|---|
| 1 | 200 | 200 | `实际拆分开票` |
| 2 | 300 | 300 | `实际拆分开票` |
| 3 | 500 | 500 | `实际拆分开票` |

项目层面保留：

| 字段 | 值 |
|---|---|
| `立项开票总次数` | 2 |
| `当前开票总次数` | 3 |
| `立项总金额` | 1000 |
| `实际开票总金额` | 1000 |
| `计划差异状态` | `实际拆分开票` |

金额合计一致时，只提示次数变化，不判为金额异常。金额合计不一致时，进入 `金额异常待核对`。

## 自动、人工和 API 分工

| 事项 | 飞书原生 | 网页人工 | API |
|---|---|---|---|
| 源表更新同步到 `源_` 表 | 是 | 否 | 定时校准兜底 |
| 新项目计划进入主表 | 是 | 异常时处理 | 兜底重算 |
| 旧项目初始化补录 | 否 | 核对不确定项 | 是 |
| 旧项目没有发票生成 1 行待补充 | 否 | 后续补真实期次 | 是 |
| 开票明细归集 | 是 | 不确定匹配时处理 | 兜底校准 |
| 实际已多开一张发票后主表多一行 | 是，或由 API 校准 | 否 | 是 |
| 未开票前人工调整计划次数 | 否 | 是 | 可辅助校验 |
| 状态和金额计算 | 是 | 否 | 校验 |
| 即将到期和逾期提醒 | 是 | 否 | 否 |
| 源记录删除后的目标失效处理 | 不稳定 | 异常确认 | 是 |
| 真实权限成员新增和移除 | 否 | 否 | 是 |
| 一键全量重算 | 否 | 点击触发 | 是 |

## 权限同步

权限按当前有效人员计算，不按历史人员计算。

- 管理员可以查看和管理全部数据。
- 项目负责人可以查看自己当前负责项目的开票和财务进度。
- 普通项目成员不能查看财务表，除非被配置为项目负责人或管理员。
- `立项时项目负责人` 只用于展示和追溯。
- `当前权限负责人` 用于权限计算。

人员离职时：

- `系统_人员权限表` 中该人员标记为 `离职`。
- API 权限同步立即将该人员移出所有高级权限角色和目标表访问权限。
- 如果离职人员仍是某项目当前负责人，该项目进入 `离职负责人待处理项目` 视图。
- 管理员将项目负责人更新为新接手人后，权限同步把新负责人加入对应权限。
- 历史任务负责人、历史审批记录、历史开票记录不修改。

## 管理员网页后台

网页后台只面向管理员，不承载日常业务录入。

建议提供按钮：

- `初始化旧项目开票计划`
- `重建项目开票进度表`
- `校准源数据`
- `同步权限`
- `查看异常数量`
- `查看最近同步日志`

日常业务数据仍在飞书多维表格里处理。

## 异常视图

主表和辅助表至少建立这些视图：

- `待人工补充旧项目`
- `待确认发票匹配`
- `金额异常待核对`
- `实际拆分开票`
- `即将到期开票`
- `开票逾期`
- `回款逾期`
- `离职负责人待处理项目`
- `源数据同步异常`

## 实施顺序

1. 停用旧 `开票回款总览` 逻辑，但不删除旧记录。
2. 新建 `项目开票进度表_试运行`。
3. 新建或整理 `开票明细归集表`。
4. 初始化 `（旧项目）开票计划补录表`。
5. 生成旧项目和新项目的第一版开票进度。
6. 用 `2026韩泰轮胎专项费用`、`202607270009`、`202607270012` 和实际拆票案例核对。
7. 配置状态公式、异常视图和提醒。
8. 配置权限 API 同步。
9. 试运行通过后，将旧表改为备份表，新表改名为 `项目开票进度表`。

## 验收标准

- 每个项目显示正确的开票总次数和当前执行次数。
- 新项目计划来自 `源_立项申请`，旧项目计划来自补录表或初始化结果。
- 实际开票日期来自开票明细表 `开票日期`。
- 回款日期和回款金额来自开票明细表。
- 一期原则上对应一张发票；实际多开票时自动生成更多当前执行期次。
- 开票前 7 天自动标记 `即将到期开票`。
- 超过计划开票日期未开票自动标记 `开票逾期`。
- 超过预计回款日期未收齐自动标记 `回款逾期`。
- 老板驾驶舱可以按项目、负责人、客户、状态、逾期金额汇总。
- 离职员工不能访问目标表格。
- 历史任务和历史记录保留原人员记录。
- 源表发生变化后，目标派生数据自动更新或被 API 校准修正。
